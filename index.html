Intertextuality experiment builder

Choose a query text and a corpus, and this page writes an experiment file for the molab notebook. There, on a free GPU, Qwen3.5-4B and Qwen3.5-27B slide a window across the corpus and rate how closely each stretch relates to the query, from 0 to 10.

Your texts stay in this browser until you download the file. Nothing is sent anywhere.

CSV format

One row per verse, line or section, with a header row. The text column holds the words; an optional reference column labels each row on the graphs and in the tables. The model only ever sees the text, joined into one passage, never the references.

reference,text
Matthew 7:1,"Judge not, that ye be not judged."
Matthew 7:2,"For with what judgment ye judge, ye shall be judged: …"

Save as UTF-8 so Greek, Hebrew and other scripts survive (spreadsheet programs call this “CSV UTF-8”). Put quotes around text that contains commas. Semicolon- and tab-separated files work too. A file with no header is read as text only (one column) or as reference, then text (two columns). The example files are good templates.

2The experiment

40 words with a step of 4 suits Greek. English needs about 1.2 to 1.4 times as many words for the same text, so about 50 words with a step of 5 covers a similar stretch.

Mark verses on the graphs (optional)

Type references from the corpus, as they appear in its reference column, separated by commas. A range like 25:15-16 works, and the shared beginning (such as “Psalm ”) can be left out. Marked verses are shaded on the graphs, and the summary compares their scores with the rest.

4Run it on molab

molab is marimo’s free cloud notebook service, with a large GPU you can switch on. Sign in with GitHub or Google.

  1. Open the notebook in molab. Open in molab
  2. Switch on the GPU with the notebook specs button in molab’s header. The notebook restarts with the GPU attached.
  3. Run all the cells with the ▶ run button at the bottom right of the notebook.
  4. Drop the experiment file into the box in section 1 of the notebook. To keep it for later sessions, upload it through the file tree in molab’s sidebar instead, then pick it from the menu below the box.
  5. Press “Run the experiments”. The first run downloads the models, about 65 GB for both, which takes most of the time; the scoring takes a few minutes.
  6. Download the results at the bottom of the notebook: the ranking of every window, graphs of relatedness along the corpus, the corpus with a bar above every word, and the raw scores.

The notebook can also run on your own computer: download intertextuality_molab.py and open it with marimo edit intertextuality_molab.py. Qwen3.5-27B needs a GPU with about 60 GB of memory.

How the score is calculated

The corpus is split into words. A window of the chosen length starts at the first word and moves forward by the step, with a final window added if needed so the last words are covered. For each window the model receives the whole query and the window’s text, never the references, and is asked for a single integer from 0 to 10:


      
Rather than taking the one number the model would write, the notebook reads the probability the model gives each answer from 0 to 10 and reports the probability-weighted average, which makes the score deterministic and sensitive to small differences between windows. Qwen3.5 thinks before answering by default; the notebook switches that off, so the answer starts straight away. Each word on the graphs gets the average score of the windows containing it.
